### Opus 5 の性能・プロンプト適応

新モデル Opus 5 のベンチマーク検証と、旧世代向けプロンプト資産の見直しに関する報告が並んだ。

#### 検証

> 新モデル Claude Opus 5 を React 習熟度ベンチマークで計測。effort=high / max の両方で計測し、Fable 5 を上回る結果を報告。記事後半は執筆者自身も Opus 5 に交代し、書き味の違いを見せている。 — @uhyo [Zenn](https://zenn.dev/uhyo/articles/react-profession-bench-14)

#### Tips

> Opus 5 公式プロンプティングガイドを読み解き、放置すると応答が長くなるため「簡潔さの指示」を基本セットにすべきと整理。公式ガイドはプロンプト内の「検証して」等の指示を削除するよう明言しており、旧 Opus 4.8 向けノウハウがそのままだと逆効果になると指摘。 — @little_hands(松岡@Loglass) [Zenn](https://zenn.dev/little_hand_s/articles/72646a09f49d2a)

### コーディングエージェントの運用知

エージェントを日常運用へ本格的に載せるなかで、失敗の蓄積やレビュー体制の作り替えに関する実践知が共有された。

#### 実践

> エージェントを並列で回しコミットが1日500超になった結果、diff を読まずマージするようになったが事故は起きていないという。「レビューでしか捕まらないもの」を先に減らす仕組みづくりを解説。 — @Isamu [Zenn](https://zenn.dev/singularity/articles/stopped-reviewing-my-code)

> Claude Code 上に役割の異なるサブエージェントを11体作り個人開発の全業務を分担。効果を出したのは凝ったプロンプトではなく「症状→誤った直感→正しい打ち手」形式で失敗をカタログ化したことだったと振り返る。 — @clar_biz [Qiita](https://qiita.com/clar_biz/items/ae903765f0d5caf5821d)

#### 検証

> Claude Code で同じ内容を複数モデルに実行させ、消費トークンを比較する実験。モデル選択とコストの関係を体験ベースで検証している。 — @tamashiro_nobuyuki [Qiita](https://qiita.com/tamashiro_nobuyuki/items/602e632ed24243cbb97c)
